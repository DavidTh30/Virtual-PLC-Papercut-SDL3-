1. บทสรุป (Executive Summary)

โฟลเดอร์ PLC_S7-1200 คือชุดโปรแกรม PLC สำหรับระบบ Fluff Silo บน Siemens S7-1200 เขียนด้วยภาษา SCL ในรูปแบบ External source (นำเข้า TIA Portal V16 ขึ้นไป แล้ว Generate blocks from source) ควบคุมอุปกรณ์ 5 ตัว ได้แก่ Blower01, Screw01, Paddle01, Paddle02 และ Paddle03 ระบบมีลำดับ Auto Start / Auto Stop, Paddle Patterns ที่ตั้งค่าได้ (สูงสุด 10 step), ระบบ Priority L1–L6 ต่ออุปกรณ์, การตรวจจับ Fault จาก overload และ running feedback, การควบคุมระดับไซโล (Fill_Request) และ interface กับ FluffSilo HMI ผ่าน DB10 แบบ PUT/GET

หัวข้อสรุป
จำนวนไฟล์17 ไฟล์ (SCL 14 ไฟล์ รวม 1051 บรรทัด, tag table 2 ไฟล์, README 1 ไฟล์)
Block ทั้งหมดUDT 1, Global DB 1, FC 5, FB 4, Instance DB 1, OB 2 = 14 block
I/ODI 15 จุด (14 บน CPU + 1 บน SM 1221), DQ 9 จุด, AI 1 จุด (IW64) รวม 25 tag
HardwareCPU 1214C DC/DC/RLY (FW ≥ V4.2) + SM 1221 DI8 + Safety relay ภายนอก
HMIDB10 "DB_HMI" Standard access 82 byte, layout ตรงกับ Default S7 Map ของ FluffSilo HMI
สถานะโค้ดครบทุก block, ผ่านการจำลอง logic ด้วย Python 31 scenario (ตาม README) แต่ยังไม่ได้ compile ใน TIA Portal
ความพร้อมพัฒนาต่อดี — โครงสร้างแยก FB ชัดเจน, ใช้ multi-instance, ตั้งค่าได้จาก HMI; มีจุดที่ควรแก้ก่อนใช้งานจริง 5 จุด (หัวข้อ 9)
ประเด็นสำคัญที่ควรแก้ก่อนใช้งานจริง: (1) Screw01 สตาร์ทไม่ติดแล้ว Sequencer ไม่ออกจาก Auto, (2) Level sensor 0-10 V ตรวจสายขาดไม่ได้ → อ่านเป็น 0 % → Fill_Request ค้าง ON (เสี่ยงไซโลล้น), (3) ต้องยืนยันว่า DB_HMI เป็น retain จริง, (4) ค่า [CFG] ใน iDB หายเมื่อ restart, (5) คำสั่ง pulse จาก HMI อาจหายในบาง scan — รายละเอียดและวิธีแก้อยู่ในหัวข้อ 9

4.2 หลักการออกแบบที่ใช้ (ควรรักษาไว้เมื่อพัฒนาต่อ)

  • ทุก I/O อ้างอิงด้วยชื่อ tag เท่านั้น อยู่ใน FB_FluffSilo ที่เดียว — FB ย่อยไม่แตะ I/O โดยตรง ทำให้ทดสอบและนำกลับมาใช้ได้
  • FB ย่อยทั้งหมดเป็น multi-instance ใน FB_FluffSilo → มี instance DB เดียว (iDB_FluffSilo)
  • ข้อมูลที่ HMI ต้องเห็น/แก้ อยู่ใน DB_HMI (absolute address) ส่วน state ภายในอยู่ใน iDB (optimized) แยกกันชัดเจน
  • คำสั่งจาก HMI เป็น pulse และ PLC เป็นผู้ล้าง (acknowledge) — ไม่มีคำสั่งค้างแม้ HMI หลุด
  • การตั้งค่าเวลาใช้หน่วย 0.1 s แบบ Int ใน DB_HMI แล้วแปลงเป็น TIME ด้วย FC_TenthsToTime
  • ใช้ REGION แบ่งส่วนโค้ด และ comment ภาษาอังกฤษในหัวไฟล์อธิบายพฤติกรรม
  • ค่า Available ของ Paddle ใช้ค่าจาก scan ก่อนหน้า (หลีกเลี่ยง algebraic loop ระหว่าง Pattern ↔ Motor)

4.3 ลำดับการทำงานใน 1 scan (FB_FluffSilo)

ลำดับREGIONการทำงาน

②External Request and parameters#extReq = ExtRequest_In OR Cmd.ExtRequest; FC_ValidateParams; แปลง Delay[0..5] เป็น TIME

5.7 FC "FC_StepBlocked" (08)

คืนค่า TRUE เมื่อ step ต้องการ Paddle (Mask & 7 ≠ 0) แต่ไม่มี Paddle ใดใน Mask ที่ Available. Step พัก (Mask = 0) ไม่เคยถูก block. Interlock ไม่ถือว่า block (Available ไม่รวม Interlock)

10. แนวทางการพัฒนาต่อ

10.1 Roadmap แนะนำ

ระยะงานผลลัพธ์ที่ต้องได้
1. ยืนยันโค้ดImport + compile ใน TIA V16+, แก้ error/warning, ตรวจ offset DB_HMI ในคอลัมน์ Offset, ทดสอบด้วย PLCSIMCompile ผ่าน 0 error; offset ตรงตาราง 6
2. แก้จุดเสี่ยงF1, F2, F3, F4, F5ผ่าน checklist หัวข้อ 12 + scenario Screw สตาร์ทไม่ติด + sensor สายขาด
3. ข้อมูลวินิจฉัยFaultCode/StartCount/ชั่วโมงทำงานไป HMI (F8, F13), ไฟ Fault กระพริบเมื่อมี fault ใหม่ผู้ใช้เห็นสาเหตุ fault บน HMI
4. ความปลอดภัยตั้ง SafeInterlock = TRUE, RestartAfterBlowerTrip = FALSE, ทบทวน risk assessmentเอกสาร PL/Category
5. ขยายระบบเพิ่มอุปกรณ์, Alarm history (Program_Alarm/ProDiag), Recipe pattern หลายชุด, OPC UA/Modbus TCPตามความต้องการ

10.2 วิธีเพิ่มอุปกรณ์ใหม่ (เช่น Paddle04)

  1. Tag table: เพิ่ม Paddle04_FB, Paddle04_OL (I8.1, I8.2) และ Paddle04_Run (Q1.1 — DQ สุดท้ายที่ว่าง)
  2. FB_FluffSilo: เพิ่ม static Paddle04 : "FB_Motor" และเรียกเหมือน Paddle03 พร้อม output
  3. DB_HMI: ห้ามขยาย Dev[0..4] เป็น [0..5] เพราะจะเลื่อน offset ทั้ง DB — ให้เพิ่ม Dev5 : "typeDevStatus" และ DevCmd5 : Array[0..7] of Bool ต่อท้ายที่ DBB82+
  4. Pattern 4 Paddle: ขยาย Mask เป็น bit3, เปลี่ยน FC_StepBlocked (W#16#000F, Available[0..3]), FB_PaddlePattern (Available/PaddleCmd [0..3]), FC_ValidateParams (Mask MX := 15)
  5. อัปเดต AnyFault, HMI register map และ README; ทดสอบ scenario Paddle fault/skip ใหม่

10.3 วิธีเพิ่มจำนวน step ของ Pattern (> 10)

  1. ขยาย Pattern.Mask / StepTime ใน DB_HMI — กระทบ offset StepTime (DBW62) ต้องพิจารณาย้ายตาราง Pattern ไปท้าย DB หรือสร้าง DB ใหม่
  2. แก้ค่าคงที่ 10 และ 9 ใน FB_PaddlePattern (LIMIT MX := 10, Array[0..9]), FC_ValidateParams, FC_LoadDefaults
  3. แนะนำใช้ค่าคงที่ (User constant) เช่น PATTERN_MAX_STEPS แทนตัวเลขตายตัว

10.4 วิธีเปลี่ยน Level sensor เป็น 4-20 mA

  1. ใส่ SB 1231 AI1 หรือ SM 1231 AI4 ตั้งช่วง 4-20 mA, แก้ address ของ Silo_Level_AI
  2. ใน FC_ScaleAnalog ค่า 4-20 mA ก็สเกล 0..27648 เหมือนเดิม; สายขาดจะได้ 32767 (overflow) หรือ -32768 ขึ้นกับโมดูล → Fault ทำงาน
  3. เปิด diagnostic 'wire break' ใน hardware config ของโมดูล

  • ใช้ค่าคงที่แทน magic number (dev×8+cmd, 27648, 10 steps)
  • พิจารณาใช้ FB_Motor เป็น Library type (Global library) เพื่อควบคุมเวอร์ชัน

13. ข้อควรระวังด้านความปลอดภัย

  • E-Stop ต้องเป็นวงจร hardware (safety relay ตัดไฟ contactor) ตาม risk assessment — S7-1200 มาตรฐานไม่ใช่ safety PLC
  • iDB_FluffSilo เป็น NON_RETAIN โดยตั้งใจเพื่อไม่ให้เครื่องสตาร์ทเองหลังไฟกลับ — อย่าเปลี่ยนเป็น retain
  • ก่อนใช้งานจริงควรตั้ง SafeInterlock = TRUE และ RestartAfterBlowerTrip = FALSE
  • เปิด PUT/GET ทำให้ใครก็ตามในเครือข่ายเขียน DB ได้ — แยก VLAN/firewall สำหรับเครือข่ายเครื่องจักร
  • ทดสอบโดยปลด power มอเตอร์ หรือใช้ Force อย่างระมัดระวัง
