# Virtual PLC (papercut, SDL3)

A simulated Siemens CPU — S7-300 (CPU 314 / 315-2 PN/DP / 317-2 PN/DP), S7-400 (412-2 PN / 414-3 PN/DP / 416-3 PN/DP) or S7-1200 (1211C / 1214C / 1215C / 1217C) or S7-1500 (1511-1 PN / 1513-1 PN / 1515-2 PN / 1516-3 PN/DP / 1518-4 PN/DP) — with its memory sizes, I/O areas, timers / counters, DB limits, accumulators and instruction times. The whole UI is papercut, drawn with BGRABitmap on all cores into an SDL3 window at 60 Hz (vsync). The PLC scan cycle runs in its own thread (1 ms, free run or the model's real cycle time).

Build: `C:\lazarus\lazbuild.exe VirtualPLC.lpi` (needs BGRABitmapPack, SDL3_package, `SDL3.dll` next to the exe).

## Screens
- **S7-1500 rules**: TIA style (`%I0.0`, optimized DBs, PUT/GET, retain flags) but with STL, 2048 S5 timers / counters and 4 accumulators for programs moved from the S7-300/400; a programming error without OB121 goes to STOP, a station failure keeps RUN; forcing on the peripheral; front panel with the display, its keys and the RUN / STOP switch; ports X1 P1R / P2R, X2 P1; S7 connect on rack 0 slot 1. Default I/O: DI32 %I0.0, DQ32 %Q0.0, AI8 %IW4, AQ4 %QW4.
- **CPU**: front panel (S7-300/400 module with SF/BF/MAINT/DC5V/FRCE/RUN/STOP LEDs and the RUN/STOP/MRES key switch; S7-1200 compact CPU with RUN/STOP, ERROR, MAINT and on-board I/O LEDs), CPU model choice, cycle time (model / host / scan period / chart), diagnostic buffer.
- **Program**: blocks (OB1, OB35/OB30, OB100, FCs), LAD networks (contacts, coils, S/R, P/N, NOT, TON/TOF/TP/TONR, S5 timers SD/SE/SP/SS/SF, CU/CD/SC, CTU/CTD/CTUD, CMP, MOVE, ADD/SUB/MUL/DIV, NORM_X, SCALE_X, CALL, branches) STL networks (S7-300/400/1500) and SCL networks (all families). Monitor: power flow in LAD, RLO / STA / ACCU 1 / ACCU 2 per STL line, the value written / condition tested per SCL line.
- **SCL** (Structured Control Language, IEC 61131-3 ST): `VAR_TEMP` locals (`#i`; also arrays `#t[#i]` and PLC data types `#s.x`, 256 bytes of L), `:=`, `IF/ELSIF/ELSE`, `CASE` with lists and ranges, `FOR .. BY`, `WHILE`, `REPEAT .. UNTIL`, `EXIT`, `CONTINUE`, `RETURN`, `REGION`, `//` and `(* *)` comments; operators with SCL priorities (`**`, unary, `* / MOD`, `+ -`, compare, `AND &`, `XOR`, `OR`); functions ABS SQRT LN EXP SIN … TRUNC ROUND MIN MAX LIMIT SEL NORM_X SCALE_X SHL SHR ROL ROR and `<type>_TO_<type>` conversions; IEC calls `"DB".T.TON(IN := .., PT := .., Q => .., ET => ..)`, `.CTU / CTD / CTUD`, also on instances in arrays: `"DB".Tm[#i].TON(..)`, `"DB".M[#i].T.TON(..)` (every element keeps its own timer state); FC calls; operands `"Tag"`, `"DB".Var`, `"DB".Arr[expression]` and `"DB".Arr[expression].Member.Sub`, also several variable indexes in one operand `"DB".M[#i].Hist[#j]` (each checked against its bounds at run time), `%MW20`. TIA type rules: implicit widening, REAL → INT needs a conversion, conditions must be BOOL; INT wraps at 16 bit, REAL is single precision. Editor with syntax colours, auto indent, Tab = 4 spaces; clicking a compiler message jumps to the line.
- **Text editor (STL and SCL, Notepad++ style)**, engine in `utextedit.pas`: selection with Shift + arrows / Home / End / PgUp / PgDn / Ctrl+Home / Ctrl+End, word moves Ctrl+Left / Right, smart Home; mouse click, Shift+click, drag, double click (word, a drag goes on by words), triple click or a click on the line numbers (lines); **column selection** with Alt+drag or Alt+Shift+arrows (typing, Backspace, Delete on every row, past the line end it pads); Ctrl+C / X / V (no selection: the line), Shift+Del, Shift+Ins, Ctrl+Ins; **undo / redo** Ctrl+Z / Ctrl+Y (Ctrl+Shift+Z) per network, typing joined like Notepad++; Ctrl+D duplicate, Ctrl+L delete line, Ctrl+Shift+Up / Down move lines, Ctrl+T swap with the line above, Ctrl+J join, Tab / Shift+Tab indent / outdent the selected lines, Backspace in the indent goes back one tab stop, Ctrl+K / Ctrl+Shift+K / Ctrl+Q comment `//`, Ctrl+U / Ctrl+Shift+U case, Insert overwrite, Ctrl+B to the matching bracket; **find / replace** bar Ctrl+F / Ctrl+H (match case, whole word, over the text networks of the block, round at the end), F3 / Shift+F3, Ctrl+F3 the word at the caret, Replace all (one undo step per network), Ctrl+G go to line; **highlights**: current line, selection, the selected word everywhere (smart highlighting), find matches, the bracket pair at the caret; **word completion** Ctrl+Space (keywords, functions, words of the block, tags, DBs and their variables). Up / Down at the first / last line goes on into the next text network.
- **Claude in the program editor** (`uclaude.pas`, `uclaudehttp.pas`, `uclaudechat.pas`, `uchatfiles.pas`): the **AI ▼** menu of the program editor has **Claude chat** (a window of its own: a second SDL window you can move, resize and keep beside the editor; closing it only hides it, the conversation stays) and **Set ANTHROPIC_API_KEY** (a dialog: save the key as the Windows user variable, like `setx`, or encrypted for this app with DPAPI; remove either) and **Remove ANTHROPIC_API_KEY** (asks first, then removes the user variable, this program's copy and the encrypted file; grey when there is no key to remove). Claude (`claude-opus-5-5`, effort high, adaptive thinking, server-side `fallbacks: "default"`, prompt caching) sees which block / network / cell is open and the text you selected, and works through tools: `get_project`, `get_block` (interface + networks: SCL / STL text, LAD as a JSON cell grid), `write_network` (SCL / STL / LAD; returns the compile messages of the block), `delete_network`, `create_block` (FC / FB, interface, instance DB), `set_interface`, `add_db_variables`, `add_tags`, `compile`, `read_values` (live values from the simulated CPU, optionally after `wait_ms`), `set_inputs` (presses the simulated buttons: digital inputs, analog channel values), `get_diagnostics`, and `download_and_run`, which asks you first (Allow / Deny). Quick actions: Fix the errors, Explain this network, Debug (live values). The chat window's menu bar: **New chat**, **Auditor ▼ Undo changes** (the whole project back as it was before Claude's first change of the last request), **Export ▼** as TXT (UTF-8), PDF (`uchatpdf.pas`: A4, the text is real text, shaped by Windows Uniscribe so Thai marks sit right, in subset embedded TrueType fonts with ToUnicode and /ActualText, so it can be selected, searched and copied; the pictures are the attached ones: a JPEG as it is, others lossless) or PNG (one tall picture). **Attach ...** (or drop files on the window) sends PNG / BMP / JPG (as PNG or JPEG, at most 1568 px on the long side), PDF (up to 20 MB) and TXT files (up to 400 KB) with the next question; attached pictures are shown in the message (and in the export, a small one in the file's chip before sending); the right button on a picture has Copy (to the Windows clipboard) and Save As ... (the picture as it was sent: PNG, or JPEG). All chat text can be selected with the mouse (drag, double click a word, triple click a message, Shift+click), Ctrl+A / Ctrl+C, and the right click menu has Copy, Copy message (its markdown) and Select all. The requests go over HTTPS with WinHTTP (no extra DLLs) on a worker thread; the tools run on the UI thread. The key comes from `ANTHROPIC_API_KEY` of the process, else of the Windows user (`HKCU\Environment`, so a key set with `setx` while the app runs counts at once), else from `%APPDATA%\VirtualPLC\claude.key` (DPAPI); never from a project file. Requests are billed to that key. `ANTHROPIC_BASE_URL` points it elsewhere (a local test server). Claude's answers are shown with their markdown tidied (tables as `·`-separated rows); Thai text is drawn from Leelawadee UI (Tahoma as a fallback), each letter with its vowels and tone marks cut as one shaped glyph.
- **Drag and drop**: an interface row (FB / FC) dragged by its grip drops `#Name` into the SCL / STL text where the red drop caret shows, or onto a LAD element as its operand (one undo step).
- **LAD selection**: a rubber band from an empty cell or a wire selects a rectangle of cells (Shift+click / Shift+arrows extend it, Ctrl+A the network, Esc back to one cell); Ctrl+C / Ctrl+X / Ctrl+V and Delete act on it, also from the **right button menu** (Copy, Cut, Paste (insert), Delete, Select all; the right button on a cell outside the selection selects it first); **Paste inserts** at the top left of the selection: in each row of the pasted block the cells from there on move right (the network gets the columns it needs, up to 32), nothing is overwritten; pressing an element (or the selection) and dragging moves it, the dashed red frame shows where; below the last row a new row is added; a move onto cells with elements or branch links is refused (wires there are replaced). Ctrl+Z / Ctrl+Y undo these LAD changes.
- **Wide LAD networks**: a network has 8 to 32 columns (`cols` in the project file when not 8); a rung grows to the right: an element in the last column, → past the last column, moving or pasting past the edge add a column, **+ Col** / **- Col** in the network head (the last column only when it is empty). 8 columns show at a time; a wider network scrolls on its own: the scroll bar under the rows (drag the thumb), Shift + wheel or a sideways wheel over the network, the view follows the focus cell, a drag near the side scrolls; the power rail stays at the left.
- **Elements panel, SCL / STL help**: the language help next to an SCL or STL network is text: drag to select (Shift+click extends, a double click takes a word and a drag goes on by words, a triple click the line), Ctrl+C / Ctrl+A or the right button (Copy, Select all), and a press inside the selection drags it into the code, where it is inserted at the red mark (one undo step).
- **Exports** (`uplcexport.pas`): the right button on a block (OB / FC / FB) exports it as text (interface, every network: SCL / STL code, LAD row by row) or JSON (as in the project file); on a network's head the network alone. CSV files are UTF-8 with a BOM, so Excel shows Thai.
- **I/O**: switches and push buttons (NO / NC), green output LEDs, analog sliders with sine / ramp generators, analog outputs, PROFINET station-failure injection. **Export I/O list (CSV)**: every DI / DQ / AI / AQ with its address, tag, input type or range, value now (and V / mA), forced.
- **Watch**: watch / modify / force table (forcing rules per family, FRCE / MAINT LEDs). **Table ▼**: Save / Open / Save As a table of its own (`*.watch`, JSON), Export (CSV with the monitor values).
- **Data blocks**: typed variables (Bool … Real, Time, S5Time, IEC_TIMER, IEC_COUNTER, arrays), offsets laid out like a standard S7 DB, start / live values, optimized access and retain on the S7-1200. The right button on a data block: export as CSV (with the values now), text or JSON; on a data type: text, CSV or JSON.
- **FC with parameters**: the same interface panel for FCs: Input, Output, InOut, Temp and a Return value (`#Ret_Val`). The parameters live in the FC's local data (before its Temps); the caller writes the Inputs into it and copies Outputs / InOuts in before and back after the call (an Output the FC does not write keeps its value). Every parameter must be given; InOuts need a variable of the same type. SCL: `"Clamp"(Value := x, Lo := 0.0, Hi := 1.0, Limited => y);` and with a Return value in expressions `r := "Clamp"(..) * 2.0;`, also from FCs and FBs. STL: `CALL FC2` / `CALL FB1, DB2` followed by parameter lines `Value := MD10` (constants for Inputs, addresses, symbols, whole structs / arrays by name; checked against the parameter size); LAD: the CALL box shows the block's parameters as pins (Input, InOut, Output =>, Ret_Val =>) edited in the properties panel, EN = 0 skips the call and the copies (ENO = EN). An FB pin left open keeps its instance value; an FC needs every Input / Output / InOut.
- **FB with parameters**: function blocks with an interface (Input, Output, InOut, Static, Temp) edited in a panel above the networks (TIA style), with the live values of the first instance DB. Instance DBs (`instance of FB` on the DB screen, or **+ Instance DB**) follow the interface. Inside the FB `#Param` / `#Static` address the instance (DI register + instance offset). Calls: SCL `"Inst_DB"(In := x, Out => y, Io := z);`, multi-instances `#inst(..)` for a Static of an FB type (`"Name"` or `FBn`), also arrays of them `#B[#i](..)`; STL `CALL FB1, DB10` / `CALL "Inst_DB"`; LAD CALL box with the instance DB as the operand (STL / LAD: the parameters in the instance DB). Inputs left out keep their instance value; InOuts are copied in and back; static IEC timers keep their state per instance.
- **PLC data types** (UDT): structs with typed members and default values, nested types; used in DBs and VAR_TEMP as `"Name"` (TIA) or `UDTn`, also `Array[0..3] of "Name"`; laid out on even bytes like S7. Access `"DB".Arr[2].Member` in LAD / STL / watch, `"DB".Arr[#i].Member` in SCL. Renaming a type updates the variables that use it. A whole struct, array or IEC instance can be assigned in SCL (`"DB".M[#i] := #a;`, `#h := "DB".M[1].Hist;`): both sides must have the same type (same PLC data type, same bounds and element type), copied as bytes; variable indexes on either side.
- **Tags**: PLC tag table (symbols), live values; **Export (CSV)** with the values now.
- **Ports**: the simulated communication ports, so real tools can talk to the virtual CPU:
  - **S7 communication** (ISO-on-TCP, TCP 102): connect with rack 0 / slot 2 (S7-300), slot 3 (S7-400), slot 1 or 0 (S7-1200) — a wrong slot is refused like on the real CPU. Setup communication (PDU 480), Read / Write Var on I Q M DB T C (bit … real), PLC STOP / start, SZL 0x0424 (mode), 0x0011 (order code), 0x001C (identification). S7-1200: "Permit PUT/GET" option, optimized DBs refuse absolute access. Works with snap7 / python-snap7, Node-RED S7, HMIs.
  - **Modbus TCP** (TCP 502): coils = Q, discrete inputs = I, input registers = IW (register n = IW 2n), holding registers = MW 2n or DBn.DBW 2n; FC 1 2 3 4 5 6 15 16.
  - Listen on 127.0.0.1 only (default, no firewall question) or on all interfaces for HMIs on the network; connection table, traffic log, self-test buttons; the port LEDs on the CPU front panel show link and telegrams.
  - All requests are served by the PLC thread at the cycle check point (consistent data).
- **Project**: samples, new / save / save as / load (`projects\*.vplc`, JSON; a file asks before it replaces the open project; with unsaved changes, closing the window, New, Load sample and Load ask **Save / Don't save / Cancel** first), cyclic interrupt interval, clock memory byte.

A developer info window (overview, performance, PLC, export) is closed at start; the **Developer ▼** menu on the Project screen shows it (F1), opens it beside the main window, keeps it on top of the other windows (Developer info on top, a check mark while on) and closes it (its own X only hides it too); export makes PNG / GIF / MP4 / SVG of the main picture and each layer (paper, sheets, ornaments, controls, text, overlay).

## Sample (motor start / stop)

The program starts with an empty S7-1200 project (CPU 1214C, OB1 "Main" with one LAD network), downloaded to the CPU in STOP.
FC1 "SpeedStats" (calling FC2 "Clamp" with a Return value for the average and FB1 "RunMeter" with its instance DB2 "RunMeter_DB" for the run seconds) is written in SCL in every family's sample (called from OB1 with a LAD CALL box): speed history in an array of the PLC data type "SpeedSample" (Rpm, Running) with a FOR loop and a variable index, the average, a CASE speed class, and FB1 whose static IEC timer counts the motor seconds.

Load it on the Project screen (or `--sample=300|400|1200`), press RUN (F5), then on I/O: turn **Overload_OK** (I0.2) on and press **Start_PB** (I0.0). The motor latches (Stop_PB I0.1 is a NC button), the 5 s timer switches **Full_Speed**, every start is counted (service after 5), the starting lamp flashes on the 1 Hz clock memory bit, the analog speed is scaled to rpm, and the cyclic interrupt counts run time.

## Command line
`--sample=300|400|1200`, `--shots folder` (scripted PNG of every screen), `--export folder [w h frames fps]`, `--bench=SECONDS`, `--novsync`, `--eventlog`.

## Tests
`test\claudemock.py`: a local stand-in for the Messages API that plays a whole tool loop (get_block, write_network + compile in parallel, download_and_run with Allow, read_values, the answer) and checks every request (headers, model and parameters, alternating roles, one tool_result per tool_use, the answers echoed unchanged with their thinking blocks): start it, then `VirtualPLC.exe --shots shots` with `ANTHROPIC_BASE_URL=http://127.0.0.1:8765`, `ANTHROPIC_API_KEY=mock-local-test`, `VPLC_CLAUDE_MOCK=1` (105 checks, results in `claudemock.log`; it attaches a TXT, a BMP and a JPG and checks their content blocks). `test\edittest.lpr`: the text engine (35 checks, `fpc -Mobjfpc -Fu.. -FuC:\lazarus\components\lazutils -FUlib edittest.lpr`). `test\plctest.lpr` (headless, 359 checks, 20 for the Claude tools, 44 of them SCL, 53 for PLC data types, VAR_TEMP arrays, variable indexes and struct assignment, 21 for FBs, 18 for FCs with parameters, 22 for STL / LAD calls with parameters, including S7 and Modbus over real sockets): STL semantics (AND before OR, nesting, accumulators, BCD, jumps, big-endian), LAD branches, S7-1200 rules, the three samples in RUN, save / load. Build with `fpc -Mobjfpc -Fu.. -FUlib plctest.lpr`. `test\porttest.py` checks the running program with snap7's exact telegrams and a Modbus request (plain sockets, no packages).
